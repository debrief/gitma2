# Feature Specification: Carrying state across gaps, against joining through them

**Feature Branch**: `027-carry-across-gaps` (developed on `claude/keen-wozniak-77td7j`)

**Created**: 2026-11-18

**Status**: Draft

**Input**: Owner decision, 2026-11-18, option B after spec 025: a registered study comparing
spec 025's joint solve with carrying state from one period to the next across the gap.
Classical, CPU only, nothing trained.

**SRD traceability**: §1 (the time-late consumer), §5 (references on the same rows, paired
statistics, fresh seeds, registration before results), §9 (owner's decisions; proposed, the
owner merges). Spec 025's panel (`experiments/20261118-tl8/review.md`): "joining is not
compared with carrying state between windows (spec 024)", first in its order.

## Background

Spec 025 found that one solve over several periods of a target, the track continuous through
gaps without bearings, beats solving each period alone (Annex B 3.10 [2.22, 4.58]), mostly by
making periods without an ownship turn of their own answerable. The obvious cheaper alternative
an analyst would use is to solve period by period and hand each period's answer on to the
next. Spec 024 (another session, PR 47) built `ctl-carry` for overlapping windows: it carries
the previous window's declared track over the rows the windows share. Across a gap there are no
shared rows, so as built it equals `ctl` alone. This study defines the carry that bridges a gap
and measures it against the joint solve and against `ctl` alone.

## Systems

- **alone**: `ctl-d1-q0.01` on each period (spec 016, unchanged).
- **joint**: spec 025's joint solve (unchanged).
- **carry**: each period solved in order on its own bearings only. The first period is `ctl`
  alone. Each later period's search replaces `ctl`'s start from nothing with a start from the
  carried state: the previous period's declared state at its last row, run forward at constant
  velocity through the gap and the period (spec 024's design: C″'s start is kept). The answer
  is declared at margin 1 with quiet probability 0.01 as `ctl` is.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Is joining still better than carrying? (Priority: P1)

The owner sees, per period after the first, carry ÷ joint and carry ÷ alone in range, course
and speed, paired with engagement intervals, on each split, with the verdict by the registered
rule.

**Independent Test**: one scoring run gives both ratios with intervals and the verdicts.

**Acceptance Scenarios**:

1. **Given** the registered rule, **When** the test seed is scored once, **Then** each
   comparison's outcome is stated per split with the median per-period ratio and the shares
   better, twice as good and twice as bad.
2. **Given** that carry is defined only from the second period on, **When** ratios are taken,
   **Then** first periods are excluded from carry's comparisons and the count stated.

### User Story 2 - Where does carrying help or fail? (Priority: P2)

A researcher sees the ratios by whether the period has its own ownship turn, by gap length,
by whether the target manoeuvred in the gap, and on rows the period determines alone.

### Edge Cases

- The previous period's declared state is missing or non-finite: carry falls back to `ctl`
  alone for that period and the fall-back is counted.
- A manoeuvre in the gap: the carried state is wrong; reported by gap content.

## Requirements *(mandatory)*

- **FR-001**: `ctl`, the joint solve and every registered code path of specs 013 to 025 MUST NOT
  change in behaviour. Carry's search, with its carried start replaced by the start from
  nothing, MUST reproduce `ctl-d1-q0.01` alone exactly (tested).
- **FR-002**: Engagements, layouts, splits and scored rows are spec 025's (layout from its own
  stream, rows by the span's bound below 0.5, also rows the period determines alone).
- **FR-003**: The decided comparisons, per split, over periods after the first, geometric mean
  of per-period ratios of period median error with 95% engagement-bootstrap intervals:
  (a) carry ÷ joint: *joining better* if the range interval is wholly above 1; *carry
  better* if wholly below 1; otherwise *not separated*; (b) alone ÷ carry: *carrying helps*
  if the range interval is wholly above 1; *carrying harms* if wholly below 1 in range,
  course or speed.
- **FR-004**: The rule, sizes (from tuning on spent seed 353) and what follows are fixed in a
  decision record before seeds 360 (validation) and 361 (test) exist; soundness as spec 025's
  second registration (per-engagement reference efficiency, a gross-fault screen, band
  [0.6, 1.6] centred on the efficient value about 0.79 per spec 025's panel) and carry
  answering at least 0.95 of periods.
- **FR-005**: Tables generated by a committed script; five-reviewer panel; kickoff and slides
  posts; AGENTS.md; SRD §9 line.

## Success Criteria *(mandatory)*

- **SC-001**: For each split the owner can read whether joining beats carrying, and whether
  carrying beats solving alone, with intervals.
- **SC-002**: The comparisons are given for periods with and without their own ownship turn and
  on rows each period determines alone.

## Assumptions

- Seeds: tuning on spent seed 353 (spec 025's test; development data, never a result);
  validation 360, test 361 (chosen clear of other sessions' registrations: spec 024/"025 long
  study" in PR 47 uses 350 and 351).
- Spec 024's `ctl-carry` as built (overlap only) is not run: on these layouts it equals `ctl`
  alone by construction (no shared rows).
- If joining is better on Annex B, the joint solve stays standing for several periods and carry
  is recorded as the cheaper, weaker alternative; if not separated or carry is better, the
  cheaper carry is recommended where it is not worse, and the owner decides.
