Gate S asked one learning question. Does a learned segmenter, L, find the target's steady legs
better than the classical segmenter, C, that it is built on? On the fresh test seed the answer is
no measurable difference: L minus C in gap recovered is +0.0014, with a 97.5% interval of
[−0.0030, +0.0051]. The pre-registered rule counts an inconclusive S4 as not passed. So C carries
into Gate 2, and learning is recorded as not shown.

The classical result is strong. C recovers 0.90 of the range-error gap between a one-leg fit and
an oracle that knows the true change times. The GLR + confirm interim segmenter recovers 0.14.

## What was tested

[SRD Annex A §A.9](https://github.com/debrief/gitma2/blob/main/docs/SRD-annex-A.md) defines three
components on the owner's manoeuvre model (generator 0.6.0, MAN2):

- **O**, the ownship segmenter, from ownship's own course and speed;
- **C**, the classical target segmenter: GLR alarms and an additive leg search nominate
  transitions, and the coupled physics-layer fit on each nomination's own prefix confirms them
  (see [steady-leg segmentation](/algorithms/segmentation));
- **L**, which is C plus learned per-bearing evidence. Untrained, L is C, byte for byte.

L's evidence network is a small causal convolution. It was trained on 10,000 scenarios from
stream seed 317 by the semi-Markov likelihood of the true segmentation, with three seeds and a
shuffled-label control. Training lowered the validation loss by under 1.5%, and the control
gained about 40% of what the best seed gained. On validation no seed beat C. The median seed
(seed 3) was frozen by SHA-256 before the test split was opened.

The [decision record](https://github.com/debrief/gitma2/tree/main/experiments/20261104-gs-decision)
fixed the four criteria, the limits, the carried-seed rule, the shuffled rule, the follow-on and a
forecast before any L training.

## The result

Seed 315: 5,059 scenarios at σ = 1°, 19,921 G5 rows, 97.5% scenario-clustered paired intervals.

| Check | Statistic | Result |
| --- | --- | --- |
| S1 | O's contamination P90 on ownship legs, limit 0.02 | 0.000 [0.000, 0.000]: **pass** |
| S2 | C − GLR + confirm, gap recovered in range | +0.755 [+0.711, +0.798]: **pass** |
| S3 | L − C, contamination P90 (limit +0.01); false splits (limit +0.05) | −0.0005 [−0.0056, +0.0034]; 0 [0, 0]: **pass** |
| S4 | L − C, gap recovered in range | +0.0014 [−0.0030, +0.0051]: **inconclusive** |

Median relative range error on all G5 rows:

| | Range | Course ° | Speed kt | Gap recovered |
| --- | --- | --- | --- | --- |
| One leg | 0.589 | 68.5 | 6.39 | 0 |
| Frozen IMM | 0.577 | 56.0 | 6.07 | — |
| GLR + confirm | 0.514 | 47.9 | 4.65 | 0.143 |
| C | 0.118 | 14.7 | 1.58 | 0.898 [0.889, 0.908] |
| L | 0.118 | 14.6 | 1.59 | 0.899 [0.890, 0.908] |
| Oracle | 0.065 | 7.4 | 0.96 | 1 |

The forecast was L − C of +0.01 [−0.01, +0.03], most likely inconclusive. The result is nearer
zero and tighter than forecast.

## Reading it

Two explanations fit, and they are not exclusive.

- **Little headroom.** C leaves 0.10 of the gap. By detectability band, C's gap recovered runs
  from 0.76 on the weakest changes to 0.96 on the strongest. Much of what is left is in changes
  that bearings at σ = 1° barely reveal.
- **The design limits L.** L's loss teaches the additive search's lattice, but C also takes
  GLR nominations (how many of its transitions come from each was not counted), and there the
  evidence can only shift a capped confirmation threshold. Only 10% of changes have both edges within ±60 s, so boundary error is
  real, but C's confirmation already puts knots where the fit needs them.

So the result says that this evidence network, trained this way, added nothing measurable. It does
not say that learning cannot help segmentation.

## Caveats

- S3's false-split check rests on only 67 change-free test rows; both segmenters split none.
- The frozen trackers are weak on MAN2 (the IMM is near one leg in range), and they were tuned on
  validation rows that include their scoring rows. Ratios against them overstate practical gains.
  The gate's criteria are differences between segmentations and do not depend on them.
- L's training jobs recorded `git_dirty`, because the workflow put downloaded tables and
  checkpoints inside the checkout. The code was clean at the training commit; the workflow is
  fixed. The gate CLI first recorded `git_dirty` from a bug (it read the tree's status after
  writing its own outputs); the record was re-run at a clean commit.

## What follows

Fixed in advance (FR-072): C is Gate 2's segmenter. Gate 2 reports its "half the gap to the
oracle" for C as well, so a Gate 2 gain is credited to the right component. Because C already
recovers 0.90 of the one-leg-to-oracle gap, Gate 2's decision record must say which gap it gates
before any result exists.

Recommended for the owner, adopted if there is no objection by the time Gate 2 is specified: test
a learned nominator, or evidence trained through the confirmation step, within Gate 2 rather than
as a separate gate.
